# 小组协作与任务历史

## 使用方式

个人云同步仍由登录流程自动准备。设置页不再提供工作区创建、切换或绑定入口；已有个人同步绑定与首次数据冲突确认继续保留。

侧栏「我的小组」提供：

- 创建小组、通过邀请码预览并申请加入，创建者批准或拒绝申请。
- 每个小组独立设置组内昵称、公开项目、排除的私密任务，以及是否公开备注。
- 每日概览按成员统计当天到期、当天完成、逾期；成员任务支持日期、成员、项目、状态和搜索筛选。
- 创建者管理申请、移除成员、更新或停用邀请码、解散小组；成员可以撤回申请或退出小组。

项目分享默认关闭。分享项目会包含以后新建的任务；排除父任务也排除其子任务。备注默认不分享。成员只有阅读权，创建者不能修改或删除成员的个人任务。

## 部署

新增迁移：`supabase/migrations/20260905022902_groups_and_history.sql`。已于 2026-09-05 应用到当前绑定的 Supabase 项目，本地文件版本与云端迁移记录一致。未重建或覆盖 EXE/APK；使用新版源码客户端即可访问小组功能。

部署验证：本地小组数据库测试通过；线上四张私有表启用 RLS，客户端无直接表权限，匿名角色不能执行小组 RPC，已登录角色可执行。通过回滚事务验证创建、默认不分享任务、概览、管理和解散接口，测试未留下小组。现有个人空间和 20 份同步快照保持不变，初始化生成 34 条任务历史基线；历史时间从部署时开始，不补造过去记录。

旧版个人同步 RPC、快照结构没有改变，旧客户端仍可同步。未应用新迁移的服务会提示「小组服务尚未启用」，个人同步不受影响。新迁移在同一数据库内完成数据表、触发器、RPC 和授权部署；部署前照常备份数据库。

## 权限模型

小组与个人 workspace 完全独立。加入小组不会把任何人加入另一个人的 `workspace_members`，也不会授予 `sync_events` 阅读权。

四张表位于未公开的 `private` schema，并启用 RLS、撤销客户端表权限：

| 表 | 用途 |
| --- | --- |
| task_groups | 创建者、小组资料、邀请码与期限 |
| group_members | 用户、组内昵称、申请说明、审批状态与加入时间 |
| group_shares | 该用户对该组的项目范围、排除任务、备注开关 |
| task_history | 各个人任务的版本与云端接收时间 |

客户端只调用 `public.groups_api(action, args)`；入口是 security invoker，内部 private 实现执行身份、成员状态、创建者权限与资源归属检查。读取只返回允许分享的字段，不返回邮箱或完整个人快照。未经批准时只可查看自己的申请/分享和邀请码指向的小组基本资料。

分享数据源必须是本人拥有且没有其他成员的个人同步空间。既有多人 workspace 不会静默迁移或被当作个人数据公开；需要先处理旧数据归属。小组阅读时也会重新检查这一条件。

邀请码采用随机 UUID 去除分隔符后的 32 位码，有效期 7 天，更新后旧码失效。邀请码不直接授予成员资格。每账号最多创建 20 组，每组最多保留 100 个成员和申请，以限制单次概览体量。线上可另外配置网关请求频率限制。

退出/移除成员时分享规则级联删除；解散小组不删除个人任务及个人历史。对历史读取同时检查当前和历史时点的项目/父任务权限，防止任务转入私密项目后旧版本仍被读取。历史查询不能越过当前这次入组/分享数据源的起始时间。分享项目后，可查看入组以来已经记录的相关历史，因此分享编辑器明确说明规则也作用于历史记录。

## 历史语义

对成功接收的个人快照，由数据库触发器提取任务白名单字段。内容未变化不新增版本；内容变化、完成/重新打开、删除/恢复都会记录。历史单独保存，不受同步快照只保留最近 20 份的策略影响。

- 使用服务端 `observed_at`，不相信客户端回填的同步事件时间。
- 历史日期展示该日本机所选时区结束前最后一个已确认版本；今天展示最新已确认版本。
- 当天完成统计当日观察到「未完成 → 已完成」的任务，每任务最多一次，子任务不计入概览统计。首次看到一个已经完成的任务不推断其完成时间。
- 启用迁移时只用最新快照建立当天基线，不伪造此前的历史。
- **现有离线 outbox 会合并快照，因此离线期间或短时间内合并掉的中间变化无法重建。** 此版本保留的是云端确认过的历史，不是每次本地点击的审计日志。若以后需要完整离线行为审计，应增加独立、幂等的本地状态事件队列。
- 历史没有自动按天清除，数据库运维应监控容量；不能直接套用快照清理策略，否则会破坏历史日期的最后有效版本。

## 缓存与刷新

协作数据只保留在页面内存，不写入 localStorage 或本地任务数据库。每 15 秒刷新，支持手动刷新；失败时清除成员任务，切换账号、离开页面或页面隐藏时清理敏感视图，并通过请求代次避免旧响应重新显示。服务端撤权立即阻止新读取，已经打开的成员页面最迟在下一次成功检查时更新；网络故障也不会持续显示旧任务。已经看过或截图保存的内容无法技术性收回。

## 验证

`npm.cmd run test:groups` 使用 PGlite（本地 PostgreSQL WASM 引擎）执行完整 SQL 迁移与实际 RPC。测试环境仅模拟 Supabase `auth.uid()`、用户表与角色，以及 uuid 扩展函数，不连接线上数据库。

覆盖匿名拒绝、跨账号快照隔离、申请审批/拒绝、昵称与分享数据归属、父子任务排除、备注开关、历史重建、快照清理后历史保留、撤销后的历史权限、邀请码更新/过期、移除与解散等。`npm.cmd run verify` 已包含此测试。

浏览器联调使用相同迁移的本地临时数据库与两个合成账号，覆盖创建→申请→审批→查看→撤权→退出，以及 1100/680/390px 布局。测试页面和截图位于被忽略的 `output/playwright/`，不打入发布包。

生产 Supabase 的真实邮件登录、网络条件、API schema 暴露配置与服务规模仍需在迁移部署后验收。
