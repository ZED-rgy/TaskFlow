# 完成记录

## 用户操作

- 保持在项目里创建、完成任务。完成记录默认显示本周（周一至周日），支持今天、本月、自选起止日期和项目筛选。
- 根任务和子任务各自完成各计一项；重复任务的下一次是新的任务 ID，独立记录。
- 每个任务最多保留一条有效完成记录。取消完成撤销该记录，再次完成使用新的时间。普通改名、移动、编辑不会改写当时的记录。
- 删除任务、清空项目任务或删除项目，均保留已生成的完成记录。删除未完成任务不会生成记录。
- 完成记录可单独确认删除，不改变原任务。该记录的标题、项目名称会从记录载荷中清除，保留最小删除标记以防旧设备恢复。
- 首次升级仅从仍存在且有合法 `completedAt` 的已完成任务补入记录；不把缺失时间补成升级时间。不从旧小组状态历史推测已经清空的个人完成记录。
- 日期、时分在完成时按设备本地时区固定，跨设备查看不重新归档。旧记录补入使用补入设备的时区，因为旧格式没有原时区信息。

## 本地持久化与备份

数据版本为 4。`completionArchive` 与任务同处本地数据文件，参与现有备份及恢复；任务完成与生成记录在同一次状态写入中处理。

记录按个人同步空间隔离；未绑定时使用空 scope。首次绑定选择合并或使用本机时，将未绑定记录一并绑定；选择云端时，原本地记录保留在本地备份/未绑定 scope 中，不上传。已属于其他账号的记录不会迁入新账号。

导入备份会补入本地尚未存在的完成记录，但不覆盖当前已有记录及其删除标记，不复制旧同步游标。账号 scope 保留。换设备或重装后，云端记录由独立接口逐页同步回本机。

## 云端与容量

迁移：`20260907095733_personal_completion_records.sql` 与 `20260907100428_completion_record_text_fields.sql`。后者保证直接调用接口的异常文本载荷不会使客户端无法读取整批记录。

`private.completion_records` 只保存任务标识、项目标识/名称、完成时标题、完成时间/本地日期/时分及同步元数据，不保存备注、标签、附件或完整任务副本。每个任务一行，更新覆盖该行，不追加无限状态事件。

原任务快照明确移除 `completionArchive`。完成记录使用独立 `completion_sync` RPC：每批最多上传 100 条待同步记录、拉取游标后的 200 条变化；每轮最多 5 页，剩余部分在下一轮继续。界面每页从本地读取 100 条。无变化不反复传输全部历史，也不反复重写本地文件。

更新使用行 revision 比较，mutation ID 保证重试幂等。同一任务多设备同时完成不会创建两条记录。过期修改发生冲突时保留服务端记录并向用户提示，避免旧设备恢复已删除记录。请求期间产生的新修改保留待同步状态，并在前一操作被确认后推进比较基线。服务端用按空间事务锁保证分页游标不跳过尚未提交的修订。

不设置静默清理期限；需监测总库容量、旧小组状态历史、实时连接和出站流量，轻量记录本身不能保证免费版支持固定用户数。此功能未改变现有小组历史保留规则。

## 权限与兼容

表启用 RLS 且不向客户端授予直读权限。RPC 仅允许当前个人空间所有者访问；加入小组不获得他人的个人完成记录。小组页面仍通过原有受控的状态历史接口展示已授权任务。

两端应同时升级：旧版本可以继续同步任务，但不会可靠生成/撤销新的个人完成记录，也不了解本地版本 4 的档案字段。不要降级覆盖含新记录的本地数据文件。

## 验证

- Rust：完成、改名、取消/重做、清空/删项目保留、账号隔离、备份往返、缺失时间、请求期间新修改保留。
- JavaScript：周/月/闰年/跨年边界、日期分组、分页、失败不确认、账号切换丢弃迟到响应。
- PGlite：完整迁移、所有者权限、拒绝表直读、幂等、删除清除文本、过期写入冲突、分页不漏记录。
- 桌面/移动浏览器：入口、默认本周、月份、项目筛选、删除确认及数量更新、空范围。
